# 2–3 minute semifinal demo script

## 0:00 — National overview

Open PasarPulse and point out the `HISTORICAL REPLAY` badge. Explain that the
system is asking what may happen next, where, and what an analyst should check.
The default map is projected movement risk, not raw price.

## 0:20 — Select context

Choose Cabai Rawit, Retail, and 7 days. Click an elevated province. Show the
current price, forecast endpoint, projected percentage, target date, model
lineage, and the transparent product warning rule.

## 0:50 — Evidence

Open Evidence. Show the PIHPS price observation and calendar/BPS context. Point
out that missing weather/satellite/propagation detail is visible rather than
silently replaced. Say explicitly that model attribution is unavailable for
this artifact.

## 1:10 — Replay

Move the timeline backward to an earlier origin. The map, queue, panel, and
Copilot context change together. Explain that only information available at
the origin drives the forecast. Press Reveal future to show realized price and
error under the retrospective evaluation label.

## 1:35 — Analyst prioritization

Open Alerts and show the ranked work queue. Filter High/Elevated. Explain that
the warning is a decision-support prioritization, not a probability or a
regulatory command.

## 1:55 — Copilot

Ask “Why is this province elevated?” then “Compare with Jawa Tengah.” The
response is grounded in the selected JSON evidence and may update approved
dashboard controls. If the Gemini key is absent, the UI explicitly reports
Copilot unavailable rather than presenting a generated fallback answer.

## 2:25 — Research credibility

Open Model. Show the saved LightGBM log-ratio benchmark, seven chronological
origins, and the distinction between implemented tree-based artifacts and the
paper's proposed multimodal/GNN roadmap.

Close with: “PasarPulse transforms fragmented food-price data into an
auditable forward-looking monitoring queue for human decision makers.”
